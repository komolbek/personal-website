# necto.uz — редизайн: сайт как инструмент подбора

Версия 1.0 · 4 сентября 2026

Этот документ — единственный источник правды по редизайну. Он заменяет
`Business/website_redesign_plan.md` (там остаётся исходный аудит и обоснование цен) и
собирает вместе: что меняем, почему, в каком порядке и какими файлами.

---

## 0. Суть изменения, одним абзацем

Сегодня necto.uz — брошюра: герой, портфолио, отзывы, FAQ, форма. Она рассказывает о
студии и надеется, что посетитель напишет. Проблема в том, что посетитель — владелец
бизнеса в Ташкенте — уходит, так и не узнав цену, потому что цены на сайте нет, а
спрашивать он не станет: боится услышать сумму, которую не потянет, и не хочет
показаться несерьёзным.

**После редизайна сайт — один инструмент: подбор программы с точной ценой.** Посетитель
отмечает, что у него не работает, и за минуту получает название пакета, сумму, срок и
короткое объяснение, почему именно так. Всё остальное — портфолио, блог, продукты, о
студии — остаётся живым и проиндексированным, но уходит из фокуса в подвал.

**Почему это выигрышно именно здесь:** по данным рынка (см.
`Business/market_analysis_tashkent.md`) **ни одна студия в Ташкенте не публикует
фиксированную цену на бизнес-систему.** Все пишут «от» или прячут цену совсем. Точная
цифра плюс объяснение, откуда она взялась, — позиция, которую сейчас никто не занимает.

## 3. Калькулятор — спецификация

Рабочий прототип: артефакт «Necto — подбор программы». Ниже — то, что нужно для
реализации в Next.js.

### 3.1 Модель данных

Положить в `src/config/calculator.ts`. Цены — единственное место, где они живут.

```ts
export type PkgId = 'task'|'dept'|'all'|'mob'|'docs'|'land'|'corp'|'shop';

export interface Pkg {
  id: PkgId;
  name: string;      // «Программа для одного отдела»
  price: number;     // сум, единоразово
  term: string;      // «4–6 недель» — для показа
  weeks: number;     // верхняя граница, для расчёта общего срока
  why: string;       // одно предложение: что это даёт
  inc: string[];     // 4 пункта, результатами а не функциями
}

export const PKG: Record<PkgId, Pkg> = { /* см. §3.6 */ };

export const ADDONS = [
  { id:'migr',  n:'Перенос данных',      s:'из Excel или из старой программы', p:4_000_000 },
  { id:'1c',    n:'Связь с 1С',          s:'данные уходят в бухгалтерию сами',  p:6_000_000 },
  { id:'bot',   n:'Бот в Telegram',      s:'заявки и статусы в мессенджере',    p:4_000_000 },
  { id:'pay',   n:'Приём оплаты картой', s:'Payme, Click, Uzum',                p:3_000_000 },
  { id:'train', n:'Обучение команды',    s:'занятие на 2 часа',                 p:1_500_000 },
] as const;

export const SUPPORT = [
  { v:'no',   t:'Пока не нужно',              p:0 },
  { v:'base', t:'Базовое — 3 000 000/мес',    p:3_000_000 },
  { v:'plus', t:'С доработками — 5 000 000/мес', p:5_000_000 },
```

### 3.2 Вопросы

| № | Вопрос | Тип | Показывается |
|---|---|---|---|
| 01 | Что в работе идёт хуже всего | **множественный** | всегда |
| 02 | Сколько человек будет работать в программе | одиночный | если выбрано ≥1 «системное» направление |
| 03 | Что нужно от сайта | одиночный | если выбрано «нас не находят» |
| 04 | Где ваши данные лежат сейчас | **множественный** | когда есть результат |
| 05 | Что добавить | множественный (чекбоксы) | когда есть результат |
| 06 | Обслуживание после запуска | одиночный | когда есть результат |

Номера пересчитываются по видимым вопросам — пропусков быть не должно.

Варианты 01: `zayavki` Теряем заявки и клиентов · `sklad` Склад не сходится ·
`raspisanie` Путаница в расписании · `vyezd` Не вижу, что делают на выезде ·
`docs` Полдня на ручной ввод документов · `site` Нас не находят в интернете

Первые три — «системные» (`k:'sys'`), они определяют основной пакет. Остальные
добавляют **отдельные позиции**, а не заменяют основную.

### 3.3 Логика подбора

```
sysPkg():
  n = число выбранных системных направлений
  если n == 0                 → нет
  если не отвечен «сколько человек» → нет      ← результат не показываем раньше
  если есть ручной выбор по лестнице → он
  если n >= 3                 → all
  если n == 2                 → size=='s' ? dept : all
  иначе                       → size: s→task, m→dept, l→all

items():
  [sysPkg]  если есть
  + mob     если выбрано «на выезде»
  + docs    если выбрано «ручной ввод»
  + kind    если выбрано «не находят» И отвечено «что нужно от сайта»
```

Итог = сумма позиций + выбранные дополнения. Срок = максимум `weeks` по позициям
(работы идут параллельно), для одной позиции — её `term` как есть.

### 3.4 Автоподбор дополнений

По ответу на вопрос 04:

| Ответ | Включается |
|---|---|
| В Excel | `migr` |
| В другой программе | `migr` + `1c` |
| В тетради или в Telegram | ничего |

Автовключённые помечаются подписью **«по вашему ответу»**. Пользователь может снять —
подпись пропадает и больше не возвращается для этого пункта. **Ничто не должно попадать
в сумму без объяснения.**

### 3.5 Блок «Почему так» — обязателен

Главное отличие от обычного калькулятора. Под позициями — 2–4 строки, объясняющие
результат словами клиента. Полный набор правил в прототипе; принципы:

- Ссылаться на **конкретные ответы**: «Два направления — заявки и склад — и больше 5 человек»
- Одно правило должно **удешевлять**: «Переносить нечего — начнём с чистого листа, так на
  неделю быстрее». Без этого блок читается как машина, которая только накручивает
- Не больше 4 строк

### 3.7 Состояния

- **Пусто** — «Здесь появится ваша цифра» + диапазоны (15–90 млн, 5–14 млн, от 2 недель).
  Посетитель, не тронувший ни одной кнопки, всё равно уходит, зная порядок цен
- **Есть результат** — позиции с «×» для удаления, «Почему так», суммы, гарантии
- **Несколько позиций** — плашка «Не обязательно всё сразу»
- **Мобильный** — липкая нижняя панель с суммой. Без неё карточка уходит за экран и
  нажатия выглядят как «ничего не произошло». Это была самая грубая ошибка первой версии

### 3.8 Заявка

Кнопка «Получить смету» → диалог с **одним** полем: телефон или Telegram. Сборка
уходит текстом. Никаких обязательных email, названия компании и «примерного бюджета» —
бюджет мы только что посчитали за него.

Отправка: существующий `src/app/api/contact/route.ts` + `src/lib/telegram-notify.ts`.
Добавить в payload: список позиций, дополнения, итог, срок, все ответы.

## 5. Дизайн-система

Бренд остаётся, декор уходит.

### 5.1 Токены

```css
:root{
  --paper:#FFFFFF; --paper-alt:#F7F8FA;
  --ink:#16181D; --ink-muted:#565E6B; --ink-faint:#8B93A1;
  --line:#E4E6EC; --line-strong:#C9CDD8;
  --accent:#4338CA;        /* ваш индиго, затемнён до 7,9:1 на белом */
  --accent-soft:#EFF0FE; --accent-line:#C3C7F7;
  --ok:#2F7A55; --flag:#9A4A22; --flag-soft:#FCF1EA;
}
```

Тёмная тема — переопределение тех же токенов под
`@media (prefers-color-scheme:dark)` с гардом `:root:not([data-theme="light"])` и под
`:root[data-theme="dark"]`.

`#6366f1` из текущего `globals.css` даёт на белом **4,47:1** — чуть ниже порога WCAG AA
(4,5:1), то есть формально не проходит для обычного текста. `#4338CA` — тот же цвет
семейства, **7,9:1**. Менять только оттенок, бренд остаётся.

Отдельно: сейчас все заголовки залиты `gradient-text` через
`-webkit-text-fill-color: transparent`. У такого текста контраст в принципе не измеряется,
и он ломается в режиме высокой контрастности. Это ещё одна причина убрать градиент.

### 5.2 Шрифты

## 6. Копирайтинг

### 6.1 Правило именования

Каждая строка начинается с одного и того же слова, меняется только объём:
**одной задачи → одного отдела → всей компании.** Никаких выдуманных названий пакетов.
Термин (CRM, ERP) — мелким шрифтом рядом, для тех, кто сравнивает вас с другими.

### 6.2 Словарь замен

Эти слова не должны встречаться в текстах для клиентов:

| Убрать | Заменить на |
|---|---|
| пилот, пилотный проект | программа для одной задачи |
| процесс, бизнес-процесс | отдел, вид работы |
| автоматизация | «заявки не теряются», «склад сходится» |
| модуль, ИИ-модуль | автоматическая обработка документов |
| интеграция | связь с… |
| роли и права доступа | кто что видит и может менять |
| админ-панель | страница управления |
| экспорт, выгрузка | можно выгрузить в Excel |
| SEO-оптимизация | настройки, чтобы вас находил Google |
| техподдержка | обслуживание |
| стек, фреймворк, архитектура, деплой | не употреблять вообще |

### 6.3 Ключевые формулировки

- H1: **«Узнайте цену за минуту, не оставляя телефон»**
- Шапка: «Цены — на сайте. Точные, а не «от»»
- Кнопка: **«Получить смету»** (не «Отправить заявку» — просит меньше, даёт больше)
- Гарантии рядом с ценой: «Эта сумма попадёт в договор» · «50% в начале, а не 100%» ·
  «Код и доступы остаются вашими»

### 6.4 Языки

Прототип — только русский. Узбекская версия обязательна перед публикацией: `ru`, `uz`,
`en` уже есть в `src/locales/`. Все строки калькулятора — туда же, ничего не хардкодить.

| `calc_area` — с какими направлениями | **Что на самом деле болит у рынка** |
| `calc_result` — пакет + сумма | Какой пакет выпадает чаще |
| `calc_ladder` — шаг по соседним вариантам | Сумма испугала |
| `calc_drop` — удаление позиции | Где именно испугала |
| `calc_submit` | Конверсия |
| `tab_open` | Какое возражение сильнее |

`calc_area` за месяц скажет о ташкентском рынке больше, чем всё, что есть сейчас: это
живой список того, что владельцы бизнеса считают своей главной проблемой. Складывать в
`hub` через существующий `src/lib/hub-lead.ts`.
